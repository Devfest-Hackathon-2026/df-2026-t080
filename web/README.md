# IntenTrip（試作）

エリアと希望を入れると、Gemini が実在する場所の候補と時間帯ごとの混雑の推定を出し、
混雑する時間と場所を避けた 1 日のスケジュールを組みます。どのエリアでも使えます。

## 動かす

### 推奨環境（uv / pnpm でローカル環境を汚さずに動かす場合）

```bash
# 1. 画面の準備（web/dist に組み立てる）
cd web
pnpm install && pnpm build

# 2. サーバーの準備と起動（プロジェクトローカルの .venv を使用）
cd ../server
uv venv
uv pip install -r requirements.txt

# 起動（http://localhost:8124）
# ※Vertex AI の Gemini を呼ぶ場合:
GOOGLE_GENAI_USE_VERTEXAI=true GOOGLE_CLOUD_PROJECT=<プロジェクト ID> GOOGLE_CLOUD_LOCATION=global \
  ZT_MODEL=<Gemini のモデル名> uv run python app.py

# ※手元のサンプル表示だけで動かす場合（Gemini 未設定でも動作可能）:
uv run python app.py
```

### 画面を直しながら開発する場合（HMR / ホットリロード）

```bash
# 8124 番でサーバーを起動した状態で、別ターミナルで実行（/api は 8124 番に流れます）
cd web && pnpm dev
```

### 従来の npm / pip を使う場合

```bash
cd web && npm install && npm run build
cd ../server && pip install -r requirements.txt
python3 app.py
```

- 認証は Application Default Credentials です（手元では `gcloud auth application-default login`）。
- `ZT_MODEL` には、Vertex AI のモデル一覧にある Gemini のモデル名を入れます（速さを優先して Flash 系）。
- 画面を直しながら見るときは `cd web && pnpm dev`（または `npm run dev`）を使います（`/api` は 8124 番のサーバーに流れます）。
- `ZT_LLM_MODULE` に、同じ `ask(prompt, model)`・`quota()` を持つ別の Python ファイルを指定すると、Gemini をそちらで呼びます（手元での試験用）。
- `ZT_LLM_PER_HOUR` は、Gemini を呼ぶ回数の 1 時間あたりの上限です（既定は 300。0 で上限なし）。上限に届くと、枠が足りないときと同じ案内を出します。1 分あたりの上限（429）でやり直した分も、1 回ずつ数えます。
- `ZT_LLM_PER_CLIENT` は、相手（接続元）ごとの 1 時間あたりの Gemini の上限です。既定は、初めてのエリアの頼みの数 × 4（今は 7 × 4 ＝ 28。1 人が 1 時間に初めてのエリアを 4 か所作れる）。プランへの頼み・乗換のスクリーンショットも同じ枠を使います（ペンギンの一言とお題は別の枠。下の表の `ZT_NOTE_PER_CLIENT`・`ZT_ODAI_PER_CLIENT`）。
- バス・電車の便を出すときは、公共交通オープンデータセンター（ODPT）の開発者サイトの鍵を `ZT_ODPT_KEY` に入れます（手元では、鍵を書いたファイルの場所を `ZT_ODPT_KEY_FILE` に入れてもよい）。鍵が無ければ、便を出さずに今までどおり動きます。

## Cloud Run に置く

チームの共通のサイトは Cloud Run に置きます。リポジトリの一番上の `Dockerfile` が、画面（pnpm で組み立て）とサーバー（uv で依存を入れる）を 1 つのコンテナに入れます。GitHub の `main` に変更が入ると、自動で組み立て直して置き直します。

### 1. Google Cloud の準備（1 回だけ）

サイトと Gemini で払うクレジットを分けるため、プロジェクトを 2 つ使います（サイト用と Gemini 用。1 つにまとめてもかまいません）。

1. サイト用のプロジェクトで、次の API を有効にします: Cloud Run Admin API・Cloud Build API・Artifact Registry API・Places API (New)。Gemini 用のプロジェクトで、Vertex AI API を有効にします。
2. サイト用のプロジェクトに、Cloud Run で動かすサービス アカウントを作ります。ロールは次の 2 つだけを付けます。
   - Gemini 用のプロジェクトの「Vertex AI ユーザー」（`roles/aiplatform.user`）。例: `gcloud projects add-iam-policy-binding <Gemini 用のプロジェクト ID> --member=serviceAccount:<サービス アカウント> --role=roles/aiplatform.user`
   - サイト用のプロジェクトの「Service Usage ユーザー」（`roles/serviceusage.serviceUsageConsumer`）。Places API を呼んで、その料金をサイト用のプロジェクトに付けるのに要ります（付けないと Places が 403 で断ります）。例: `gcloud projects add-iam-policy-binding <サイト用のプロジェクト ID> --member=serviceAccount:<サービス アカウント> --role=roles/serviceusage.serviceUsageConsumer`
   - 新しいプロジェクトでは、組織のポリシーでサービス アカウントの鍵を作れません。鍵は要りません（Cloud Run の中では、サービス アカウントとして Vertex AI を呼びます）。
3. 新しいプロジェクトでは、ビルドに使う既定のサービス アカウント（`<プロジェクト番号>-compute@developer.gserviceaccount.com`）にロールが自動で付きません。サイト用のプロジェクトで「Cloud Build サービス アカウント」（`roles/cloudbuild.builds.builder`）を付けます。付けないと、ビルドが権限の不足で止まります。
4. 予算アラート（10・15・20 ドル）を設定しておきます（plan.md のとおり）。**アラートだけの予算は知らせるだけで、超えても止まりません**（Cloud Billing の予算のページ: "Setting an alerts-only budget doesn't automatically cap ... usage or spending."）。
   - 止める手段は、まず `ZT_LLM_PER_HOUR`（1 時間あたりの Gemini の回数）と、Vertex AI のクォータです。
   - 予算には別に「上限（spend cap）の予算」があり、Cloud Run はその対象です（Cloud Run のページ: 上限に届くと Cloud Run の動きをすべて止め、手で上限を外すか翌月まで止まったまま）。ただし、使えるのは対応するサービスとアカウントだけで、無料トライアルのアカウントで使えるか、Vertex AI（Gemini）が対象かは確かめられていません。予算の画面で選べないときは、上のアラートと `ZT_LLM_PER_HOUR` で抑えます。
   - ハッカソンの $20 の請求先アカウントはクレジットを使い切っても止まらず、カードに請求が始まります。100% の知らせが来たら、その目安です。

### 2. GitHub とつないで置く（コンソールで）

1. Cloud Run の「サービスを作成」を開き、「リポジトリから継続的にデプロイする」を選んで「Cloud Build を設定」を押します。
2. 「GitHub」を選び、`v76nl/devfest-hackathon-2026` を接続します（初めてのときは Cloud Build の GitHub アプリを入れる画面が出ます）。
3. ブランチは `^main$`、ビルドの種類は「Dockerfile」、ソースの場所は `/Dockerfile` にして保存します。
   - 地図を Google マップにするときは、できたトリガー（Cloud Build の「トリガー」）の「Build docker」の手順に `--build-arg VITE_GOOGLE_MAPS_KEY=$_MAPS_KEY` を足し、置換の値に `_MAPS_KEY`（Maps JavaScript API のキー・使えるサイトを Cloud Run の URL などに絞る）を入れます。地図の見た目はコード（`web/src/lib/mapStyle.ts`）で決めるので、マップ ID は要りません。入れないと、地図は MapLibre のままです。
4. サービスの設定を、次のとおりにします。

| 項目 | 値 | 理由 |
|---|---|---|
| リージョン | `asia-northeast1`（東京） | |
| 認証 | 未認証の呼び出しを許可 | 審査で URL を開けるように |
| CPU の割り当て | リクエストの処理中だけ（リクエスト ベースの課金・最初の値のまま） | 使っていない間は課金されない。プランを作っている間は、画面の問い合わせ（`GET /api/jobs/<id>?after=`）を最大 20 秒待たせて開いたままにするので、裏の仕事にも CPU が回る |
| 最小 / 最大インスタンス数 | 0 / 1 | プランを作る仕事の進み具合と、回数の上限の数をメモリに持つため（2 つに分かれると見失い、上限もそれぞれで数える）。費用の上限にもなる |
| メモリ / タイムアウト | 1 GiB / 300 秒 | |
| サービス アカウント | 1 の 2 で作ったもの | |

5. 「変数とシークレット」で、次の環境変数を入れます（鍵は要りません。サービス アカウントで Vertex AI を呼びます）。

| 名前 | 値 |
|---|---|
| `GOOGLE_GENAI_USE_VERTEXAI` | `true` |
| `GOOGLE_GENAI_USE_ENTERPRISE` | `true`（google-genai 3 の新しい名前。上と同じ意味で、両方入れておく） |
| `GOOGLE_CLOUD_PROJECT` | Gemini 用のプロジェクト ID（Gemini の料金はこのプロジェクトに付く） |
| `GOOGLE_CLOUD_LOCATION` | `global` |
| `ZT_MODEL` | Vertex AI のモデル一覧にある Flash 系の Gemini（例: `gemini-3.8-flash`。新しいプロジェクトでは `gemini-2.5-flash` は使えなかった） |
| `ZT_THINKING` | `LOW`（考える量。入れなくても `LOW`。既定の量にすると 1 回が約 2 倍遅く、考える分のトークンも払う） |
| `ZT_LLM_PER_HOUR` | `60`（1 時間あたりの Gemini の上限。初めてのエリアは 1 回で 7 回（希望があれば 8 回）呼ぶので、1 時間に 7〜8 エリアほど） |

| `ZT_PLACES_PER_DAY` | `0`（直前の 24 時間の Places の上限。0 で上限なし。叩き続けられたときの 1 日のお金の天井になる。数えるのはサーバーのメモリの中なので、置き直すと 0 から） |
| `ZT_PLACES_BULK_PER_DAY` | 入れなければ `ZT_PLACES_PER_DAY` の 3 分の 1（1 日のうち、まとめての照合に使える回数） |

| `ZT_AREA_SEARCH_PER_CLIENT` | `10`（「この付近で検索」の 1 人 1 時間の上限） |
| `ZT_AREA_SEARCH_ALL_PER_HOUR` | `60`（「この付近で検索」の全体の 1 時間の上限） |

| `ZT_NOTE_ALL_PER_HOUR` | 入れなくてよい（ペンギンの一言の、全体の 1 時間の上限。入れなければ `ZT_LLM_PER_HOUR` の 4 分の 1（最低 10。`ZT_LLM_PER_HOUR` が 0 なら 120）。Gemini の全体の上限にも数える） |
| `ZT_ODAI_PER_CLIENT` | `9`（お題の、1 人あたり 1 時間の上限。1 回押すと場所の数〈1〜3〉だけ呼ぶ。エリアづくりの `ZT_LLM_PER_CLIENT` とは別に数える。0 で上限なし） |
| `ZT_ODAI_ALL_PER_HOUR` | 入れなくてよい（お題の、全体の 1 時間の上限。入れなければ `ZT_LLM_PER_HOUR` の 4 分の 1（最低 10。`ZT_LLM_PER_HOUR` が 0 なら 120）。Gemini の全体の上限にも数える。届いたら画面は例のお題に替える） |

| `ZT_CONTACT` | 出典の文に出す問い合わせ先（ODPT のガイドライン 3.1。開発者のメールアドレス）。入れないと、問い合わせ先の一文を出さない |
| `ZT_BUS_PER_HOUR` | `240`（バスの便・目安の表を聞く回数の、1 人あたり 1 時間の上限。プランを 1 回組むと区間の数だけ聞く。0 で上限なし） |
| `ZT_BUS_ALL_PER_HOUR` | `3000`（同じく、全体の 1 時間の上限。時刻表を外から丸ごと集められないようにする。0 で上限なし） |
| `ZT_BUS_MEM_MB` | `300`（メモリに置く時刻表の表の合計の上限。超えたら古く使った物から外す） |
| `ZT_RAIL` | 入れなくてよい（`0` で OSM の路線からの電車の目安を使わない） |
| `ZT_RAIL_PER_DAY` | `100`（Overpass に聞く 1 日の上限。0 で上限なし） |
| `ZT_PROXY_HOPS` | 入れなくてよい（`X-Forwarded-For` を書き足す前の段の数。相手ごとの回数の上限は、その後ろから何個目かで相手を見分ける。入れなければ、Cloud Run では 1（`run.app` の URL に直に来るとき、Cloud Run が最後に足すのが相手の住所）、手元で直に開くときは 0（相手が書き換えられるので見ない）。Cloud Run の前にロードバランサを置くときは 2（ロードバランサのページ: 「相手の住所,ロードバランサの住所」を後ろに足し、それより前は確かめない）） |

| `ZT_FIREBASE_CONFIG` | Firebase の Web の設定の JSON（Google のログインと旅の保存。手順は `data/auth-and-trips.md`）。入れないと、ログインの部品を出さず、今までどおり端末だけに取っておく |

6. 「作成」を押します。数分で URL が出ます。

### 3. 確かめる

- URL を開くと、ホーム画面（自分の旅の一覧と「新しい旅を作る」「京都のデモを試す」）から始まります。`?start=pick` を付けると、例のエリア（京都）の地図と候補の「行きたい場所を選んでください」の画面から始まります。
- 「エリアを変更」で新しいエリアを作ると、20〜25 秒で、そのエリアの候補から選ぶ画面が出ます（Gemini を呼べているかの確認）。
- 出ないときは、Cloud Run の「ログ」で `Gemini の呼び出しに失敗しました` の行と、その番号（403 ならロール、404 ならモデル名か場所）を見ます。`枠` は 1 分あたりの上限に当たったときで、サーバーが待ってから 3 回までやり直します。
- 新しいエリアを作ると、ログに `[places] '<エリア>': 照合 〇 件・見つかった 〇 件` の行が出ます（Places を呼べているかの確認）。地図が Google マップのときは、場所の画面に Google の写真・評価・営業時間が出ます。
- Places が出ないときは、ログの `[places] search の呼び出しに失敗しました（403 PERMISSION_DENIED）` のような行の番号を見ます（403 なら Service Usage ユーザーのロールか、Places API (New) の有効化）。`トークンを取れませんでした` はサービス アカウントのトークンが取れないときです。

### 知っておくこと

- 審査の日にプランの作成が目に見えて遅いときは、その期間だけ「CPU を常に割り当てる」に切り替えます。インスタンスが動いている間ずっと課金され、1 台を 24 時間動かすと 1 日約 1.7 ドルです（東京・1 vCPU・1 GiB）。
- 回数の上限（`ZT_LLM_PER_HOUR`・`ZT_LLM_PER_DAY`・`ZT_PLACES_PER_HOUR`・`ZT_PLACES_PER_DAY` など）は、サーバーのメモリの中で数えます。置き直したときや、使われずに止まったあとは 0 から数え直すので、1 日の上限は「1 つの入れ物が動いている間の 24 時間」の上限です。入れ物が 2 つあればそれぞれで数えるので、最大インスタンス数は 1 のままにします。置き直しに左右されない天井は、Google Cloud のコンソールの「割り当て」（Vertex AI・Places API のクォータ）と予算アラートで決めます。
- 作り置き（`server/cache/`）はコンテナの中にあるので、置き直したときや、使われずに止まったあと（最小インスタンス数 0 なら、15 分ほど使われないと止まる）は消えます。そのあと初めて開くエリアは、Gemini に頼み直します（30 秒ほど）。

### 審査の前にすること

1. 審査の期間（動画の撮影 11/10・11/13〜15・11/27）は、`main` にマージしません。マージすると自動で置き直され、作り置きが消えます。
2. 審査の時間帯だけ、最小インスタンス数を 1 にして、止まらないようにします（使われていない間も課金され、1 vCPU・1 GiB で 1 日約 0.4 ドル）。
   - 始める: `gcloud run services update intentrip --region asia-northeast1 --min-instances 1`
   - 終わる: `gcloud run services update intentrip --region asia-northeast1 --min-instances 0`
3. そのあと、審査で使うエリアを 1 つずつ開いて温めます。「調整」→「新しいプランを作成」で作ると、2 回目からは作り置きからすぐ出ます（1 エリアで 30 秒ほど・Gemini を 6 回）。京都の例は作り置きが要りません（`server/sample.json`・英語は `server/sample.en.json`）。
   作り置きは言語ごとに分かれるので、英語の画面で見せるエリアは、英語の画面でも 1 回ずつ作って温めます（同じく Gemini を 6 回）。
4. 温めたあとで置き直したり、最小インスタンス数を 0 に戻したりすると、また消えます。
- 置き直しは、`main` に入ってから数分かかります。Cloud Build の「履歴」で進み具合を見られます。
- Places の規約に合わせて、サーバーが取っておくのは place_id と緯度経度（30 日まで）だけです。写真・評価・営業時間は場所の画面を開いたときに取り、取っておきません。Places の内容は Google 以外の地図（MapLibre）とは一緒に出せないので、地図が Google マップのときだけ出します。
- Places の料金（毎月の無料の回数）: 照合の Text Search（Pro）は 5,000 回、場所の画面の Place Details（Enterprise）は 1,000 回、写真は 1,000 回まで無料です。
- コマンドで置く場合（参考）: `gcloud run deploy intentrip --source . --project <サイト用のプロジェクト ID> --region asia-northeast1 --allow-unauthenticated --min-instances 0 --max-instances 1 --memory 1Gi --timeout 300 --service-account <サービス アカウント> --set-env-vars GOOGLE_GENAI_USE_VERTEXAI=true,GOOGLE_GENAI_USE_ENTERPRISE=true,GOOGLE_CLOUD_PROJECT=<Gemini 用のプロジェクト ID>,GOOGLE_CLOUD_LOCATION=global,ZT_MODEL=<モデル名>,ZT_LLM_PER_HOUR=60,ZT_PLACES_PROJECT=<サイト用のプロジェクト ID>,ZT_PLACES_PER_HOUR=300`。アップロードから外すものは一番上の `.gcloudignore` に書いてあります（`data` と書くと `web/src/data` まで外れるので、一番上の文書は `/data` と書く）。
- 手元でコンテナを試す: `docker build -t intentrip .` → `docker run -p 8080:8080 intentrip`（Gemini の環境変数が無くても、例の表示までは動きます）。
- 手元で Places を試す: サービス アカウントの鍵の代わりに、`ZT_GCLOUD_TOKEN_CMD="gcloud auth print-access-token"` を入れると、そのコマンドが出すトークンで呼びます（5 分ごとに取り直す）。

## 開発者ツールで API の呼び出しを見る

画面から出す API の呼び出し（`/api/...` と天気）は、ブラウザの開発者ツールの **Console** に残ります（`web/src/lib/apiLog.ts`）。

- 1 件ごとに `#番号 メソッド パス → 状態 時間` が出ます。押して開くと、**送った内容**と**返事**の要約が見られます（長い文字・写真のデータ・長い配列は縮めてあります）。
- 返事に `error` が入っているもの（例: `{"error": "quota"}`）と、状態が 400 以上のものは、開いたまま、赤い文字で出ます。通信そのものの失敗は、`console.error` で出ます。
- プランの進み具合の問い合わせ（`GET /api/jobs/<id>`）は、数が多いので `debug` レベルです。見るには、Console のレベルの選択で **「Verbose」** を有効にします。
- 止めるには、Console で `localStorage.setItem('intentrip:apilog', '0')` を実行して再読み込みします（戻すときは `removeItem`）。
- Google マップの地図や写真（`<img>`）の読み込みは、ここには出ません。**Network** のタブで見ます。

## 仕組み

### 候補を集める（`server/`）

1. 画面がエリアと希望を送ります（`POST /api/jobs`）。
2. サーバーが Gemini に、7 つの小さい頼み（希望があれば 8 つ）を 2 段に分けて投げます（`server/places.py` の `TASKS`・`AFTER`）。
   - 1 段目（同時に投げる）: 人気スポット 8 件（エリアの中心・出発する駅・地区も）・飲食店 8 件・カフェ 4 件・切り口（そのエリアを楽しむ観点 6 つと、そのエリアの定番の名前）・希望の読み取り
   - 2 段目（切り口・人気スポット・飲食店がそろってから投げる）: 切り口を 2 つずつ受け持つ 3 つの頼みで、切り口ごとに隠れた名所を 3 件ずつ。定番の名前とほかの切り口を渡して重ならないようにし、候補には切り口の名前（`theme`）を付けます。切り口の頼みが失敗したときは、切り口の型（店と手仕事・文化・道と地形など）だけを渡して、切り口を自分で決めさせます。
   - 2 段目は 1 本が長いので、全員で分け合う Gemini の同時枠（6）とは別の枠（3）で投げます。
   - 候補ごとに、地区・知名度（1〜5）・向いている時間帯・休日の 8〜18 時の混雑（0〜4）・営業時間・滞在の目安・特徴・注意点・推定の根拠を出させます。
   - 京都のような広いエリアは、地区（東山・嵐山・洛北・伏見など）に散らばるように出させます。
3. **人気スポットと飲食店がそろった時点（どちらかが失敗しても、届いた分で）で、先にプランを出します**（`state: ready`）。残りの候補は届くたびに差し替えます（`version` が上がる）。行きたい場所を選ぶ画面では、隠れた名所を切り口ごとの見出しで並べます。
4. 位置は地図データ（OpenStreetMap の Nominatim）で裏で確かめ、近くに同じ名前があればその位置に直します。エリアの範囲から大きく外れる候補は外します。
5. あわせて裏で、写真と移動時間の表を足します（`server/enrich.py`）。
   - **写真**: Wikipedia（日本語）で、場所の近く（1.2 km 以内）にある同じ名前の記事の写真を探します。見つからなければ、名前の書き方（括弧の中の別名・支店や本堂の語を外した名前・「山頂」「湖畔」などを外した名前・ヶとケ）で、題がぴったり同じ記事（2 km 以内）を引きます。記事に位置がないときは、記事の短い説明にエリアか地区の名前があるものだけ採ります。
     - 記事の写真が無い・地図だった場所は、Wikidata の代表の写真（P18）を使います（記事の項目か、名前がぴったり同じで 2 km 以内の項目）。
     - 違う物の写真は出しません。記事の一節への転送・町の記事への転送・曖昧さ回避の記事・名前の最初の語だけに合う記事・町や地域の項目は使いません。
     - 作り置きは、場所の名前と位置（およそ 1 km の升目）で分けます（同じ名前の別の場所の写真を使わない）。
     - Wikipedia と Wikidata は問い合わせが多いと断るので、エリアごとに数回へまとめ、どちらも 1 つずつ 2.5 秒ずつあけて送ります（Wikidata は 1 エリアで 1〜3 回。名前を 60 件ずつまとめて送る）。写真の出典は詳細の画面に出します（ライセンスは各写真のページ）。
   - **移動時間**: OpenStreetMap の OSRM で、全部の場所どうしの徒歩と車の所要時間の表を作ります。公共交通機関の目安は、下の「バスの便」の目安の表があればそれを使い、無い組み（電車の区間・乗換が要る区間・静的な版）は車の所要時間からの式（車で 10 分までは 12 分 ＋ 3 倍、それより遠い区間は 1 分あたり 2 分ずつ。車の時間が無いときは、3 km までは 10 分 ＋ 1 km あたり 10 分、それより遠い区間は 1 km あたり 3 分ずつ）で見積もります。式は、京都・浅草・横浜・箱根・日光の場所どうしで目安の表と比べて合わせました（歩くと 20 分を超える 1,549 組。エリアごとの表との比の中央値 0.97〜1.16）。
6. エリアの候補は希望によらず `server/cache/` に取っておくので、同じエリアなら 2 回目からは希望の読み取りだけで済みます。1 段目がそろった時点で途中の印（`partial`）を付けていったん取っておき、2 段目が済んだら上書きします（2 段目の途中で同じエリアの希望を頼んでも、希望の読み取りだけで済む）。2 段目が全部失敗したエリアは取っておきません。

**公共交通機関の実際の経路**: 区間の「実際の経路を入れる」から、Google マップや乗換案内の経路のスクリーンショットを選ぶと、Gemini が画像から路線・乗る駅と降りる駅・時刻・運賃を読み取ります（`POST /api/transit-shot`・`server/transit.py`）。読み取った所要時間でスケジュールを組み直し、区間には路線と時刻を出します。Google の API では日本の電車の経路が出ないため、本人が見た経路を取り込む形にしています。全自動にするなら、日本の乗換の API（NAVITIME の totalnavi など。経路・運賃・線路に沿った線が取れる）を足します。

**バス・電車の便**: エリアにかかる時刻表（GTFS）を、初めて聞かれたときに取って、探すのに要る分だけの小さな表にして持ちます（`server/bus.py`）。どの時刻表を使うかは `server/bus_feeds.py` が選びます。
- 出どころ: ODPT 会員ポータルの一覧（事業者ごと）と、CKAN にだけある物（都営バス・都営の電車・東京メトロ・りんかい線・つくばエクスプレス・多摩モノレール・西武バスなど）、GTFS データリポジトリ（範囲で絞った一覧）。ODPT の物の停留所の範囲は `server/bus_catalog.json`（`python3 bus_feeds.py --seed <鍵のファイル>` で作り直す）にあり、一覧に新しく増えた時刻表は作り直すまで使いません。
- 選び方: プランの場所を囲む範囲の中に、停留所が 2 つ以上ある時刻表だけを取ります（高速バスの終点だけがある物は取らない）。同じ事業者が両方の出どころにあれば ODPT の物を使います。
- ライセンス: 出典の表示で済む物（公共交通オープンデータ基本ライセンス・CC BY・CC0）だけを使います。CC BY-SA・ODbL などの同じ条件で再配布を求める物、チャレンジ限定（京都市営地下鉄・JR 東日本・東武・京王・相鉄など）・事前の承認が要る物（下電バスの基本ライセンス版）・GTFS-RU ライセンスの物（宇野バス・下電バス・函館市電）は使いません。予約して乗る物・乗れる人が決まっている物も外します。
- 大きな時刻表: zip が 6 MB より大きい物（都営バス・川崎市バス）は、エリアを 5 km ほど広げた範囲の停留所と、そこに停まる便だけの形にします。zip は残し、別のエリアの形はそこから作ります。
- 冷えたサーバーで目安の表が届くまで（このマシン・作り置きなし）: 浅草 22 秒（都営バスを作るのに 12 秒）・京都 16 秒・横浜 11 秒・箱根 3 秒・日光 2 秒。時刻表の無い鎌倉・奈良は 1 秒で「無し」を返します。メモリの山は浅草で 160 MB ほど。
- 版はプランの日までに始まった最後の版を選び、取ってから 7 日を過ぎたら取り直します（ガイドライン 2.2.2）。
- `GET /api/bus`: 区間の 2 地点のそれぞれ 800 m までの停留所や駅から、その日に走る乗換なしの便を、着く時刻の早い順に 3 つまで返します（乗る区間の路線の線・路線の色・歩く／乗る／歩くの 3 つに分けた線つき。形の無いバスは停留所を順に経由する車の道の線、電車は駅を結ぶ線）。画面は電車・バスの区間にいちばん早く着く便を 1 行で出し、押すとシートでほかの便と選べます。選ぶとその便の時刻でスケジュールを組み直し、地図の線を路線の線にします。
- `POST /api/bus-table`: エリアの場所どうしの「戸口から戸口まで」（停留所や駅まで歩く・待つ（15 分まで）・乗る・歩く）の目安の表を、プランの時間帯の 1 時間ごとの中央値で返します。プランの組み立ての電車・バスの時間に使います。エリアを開いて最初のプランは、この表を 2.5 秒まで待ってから組みます。
- `GET /api/bus-info?box=南,西,北,東`: エリアで便を出せるか・出典の問い合わせ先。冷えたサーバーがエリアの時刻表を取り始めるので、プランを開いたときに呼びます。
- 出典は、便のシートとプランの下に、使った時刻表（出している便と目安の表に使った物）ごとに出します。ODPT の物があればガイドライン 3.1 の文（基本ライセンス第 10 条 3 項）、続けて事業者・データの名前・版の日付・ライセンス（CC BY・CC0 はその名前と URL）・取得日時です。時刻表を外から丸ごと取れないよう、返すのは 1 回に要る分だけで、回数に上限を付けます（基本ライセンス第 8 条 4 項）。路線の色は時刻表に書いてあるとおりに返します（ガイドライン 4）。Gemini には便・時刻表・目安の表を渡しません。共有の文にも便の中身は書きません。
- JR 西日本・京阪・阪急・近鉄・京急・江ノ電などの時刻表は、ODPT にも GTFS データリポジトリにも無いため、その区間に便は出ません（「経路を見る」・スクリーンショットの取り込み）。
- 電車の目安（`server/rail.py`）: 時刻表の無いエリアでは、OpenStreetMap の路線（route relation の駅の並びと色）を Overpass API で取り、乗換なしの電車の戸口から戸口まで（駅まで歩く・待つ・乗る・歩く）の目安で埋めます。時刻表ではないので発車の時刻は出しません。乗る時間は駅の間の直線 × 1.1 と種類ごとの速さ、待つ時間は interval タグの半分（無ければ種類ごとの値）です。新幹線・寝台と、別の料金が要る特急は使いません。範囲ごとに 1 回だけ取って `cache/rail/` に 14 日置き、Overpass には 1 度に 1 つ・5 秒あけて・1 日 100 回までしか聞きません。`bus-table` は、時刻表の無いエリアだけ、組みごとの電車の目安と `rail`（乗る路線・駅・内訳 `opts` と組みごとの番号 `via`）を返します。時刻表のあるエリアは、今までどおり時刻表の表だけで、路線も取りません（作り置きの路線のあるなしで、同じ条件のプランが変わらないように）。出典は © OpenStreetMap contributors（ODbL）。上の時刻表の「ODbL などは使わない」は時刻表（GTFS）の決まりで、路線のデータは作り置きを配らず、画面と共有の画像には目安の時間・路線名・駅名だけを出典つきで出します（ODbL の Produced Work）。時刻表の無いエリアでは、最初のプランを出すときに、候補を 2 km ほど広げた範囲の路線を取り始めます。直線で 1.2 km より近い組み（画面がいつも徒歩にする）は求めません。

地図の線は、プランの区間ごとに OSRM で道に沿った経路を取って描きます（`POST /api/legs`）。徒歩は浅葱の丸い点（地の色の縁つき・直径 7px を 12px おき。値は `lib/walkDots.ts`。2 つの地図と共有の画像で同じ見え方）、公共交通機関は実線です。日本の電車の経路は取れないため、公共交通機関の線は道に沿った線（バスに近い）になります。

- 便を選んだ区間は、線を停留所まで歩く・乗る・停留所から歩くの 3 つに分け、乗る所をその路線の色で塗ります。色は時刻表の route_color を書いてあるとおりに使い（ガイドライン 4）、無ければ路線の名前から決まる色（同じ名前ならいつも同じ色。10 色の並びから選ぶ）にします。
- 乗換のスクリーンショットを入れた区間は、駅の位置が分からないので、道に沿った線を段ごとの道のりの目安（1 分に進む距離 × 分）の割合で切り、乗る段を路線の名前から決まる色、歩く段を徒歩と同じ丸い点にします。
- 便も乗換も入れていない区間は、どの路線か決まっていないので浅葱の実線です。
- 乗る所の線には縁取りを付けます（明るい画面ではその色を濃くした色、暗い画面では地図の地の色）。スケジュールの区間の行でも、路線名の頭に同じ色の小さな印を付けます（`lib/lineColor.ts`・`lib/legPieces.ts`）。
- 道に沿った線が届くまでは直線の薄い点線で描き、その間は地図の左上に「道を調べています……」を出します（押せない表示で、地図の操作をふさがない）。

かかる時間（2026-11-05 の試験）: 初めてのエリアはプランが出るまで 20〜25 秒（奈良 22.6 秒）、取ってあるエリアはすぐ。位置の確認は裏で 1〜2 分です。

### スケジュールを組む（`web/src/lib/planner.ts`・画面の裏の作業場で計算）

時刻の計算と回る順番は Gemini にさせません（間に合わないスケジュールを作るため）。

- **行く値打ち**: 人気スポットは知名度に応じて高く、隠れた名所は低め。切り口のある隠れた名所の見どころは少し上がります。希望の条件に合うと上がり、位置を確認できない場所は下がります。同じ地区・寺社・切り口が続くと少しずつ下がります。
- **混雑**: 混雑するほど値打ちが下がります（非常に混雑なら 3 割ほどまで）。希望に「有名な場所」があると、人気スポットの下がり方は半分です。
- **損**: 移動時間・乗り物に乗る手間・営業開始までの待ち・向いていない時間帯（夜の通りを朝に行くなど）・到着の予定より遅れる分・**到着の予定より早く終わって余る時間**（余るのも損に数えるので、到着の時刻まで埋めます）。
- **組み方**: 行きたい人気スポット・昼食（・19 時以降まで選んだときは夕食）を入れ、得になる場所を到着の時刻まで足します。そのあと、入れ替え・順番を逆にする・足す・外す・取り替える、を数千回試す（焼きなまし法）ことで良くします。同じ条件なら同じプランになります。
- **1 か所だけ変えたとき**（滞在・外す・入れ替え・行きたい場所・この近く・回る地区・経路）: 前のプランの並びを土台にして、変えた所だけを直します。入れ替えた場所は元の位置（時刻）に入り、ほかの場所は入れ替わりません。時間が足りなくなったら外してよい場所から外し、空いたら見どころを足して、帯で「時間に合わせて〇〇を外しました」「空いた時間に〇〇を入れました」と知らせます。日付・時刻・条件を変えたときは、はじめから組み直します。
- **入れた経路（スクリーンショット）**: 読み取った出発・到着の時刻があれば、その便に合わせます（前の場所にその時刻までとどまる）。間に合わないときは「〇〇発に間に合いません」と出します。
- **閉まる時刻**: 閉まる時刻を過ぎて滞在する場所は、間に合う位置へ移します。移せないときは「〇〇に閉まります」と出します。

### プランを変える（`web/src/App.tsx`）

- 場所の詳細から: 滞在の長さを 5 分刻みで決める（「−」「＋」か一覧から。決めた長さは組み直しても変えない・「自動に戻す」で戻す）、プランから外す、「この近くをもっと回る」（その場所から 1.5 km 以内の見どころを 2 か所まで、すぐあとに入れる）、ほかの候補に変更（食事・休憩は近くの店を先に出す）。手を入れた場所は、組み直しても外しません。
- 「場所を足す・外す」から: 見どころ・食事・カフェごと、地区ごとに候補を並べ、チェックを付けた場所を必ず入れ、外した場所はプランから外す（`PlacePicker.tsx`）。開いている間は並びを変えません（押した行が動かないように）。食事（昼食・夕食）とカフェは 1 か所ずつで、選ぶとその位置で入れ替わります。回らない地区の場所を選ぶと、その地区を回る地区に戻します。
- 「調整」から: 日付・出発（5:00〜22:00）・到着（出発の 1 時間後〜23:55）、希望から読み取った条件、回る地区。旅の当日は「今から」で出発を今の時刻にできます。外した地区の場所は、行きたい場所に選んでいても外します。
- 変えたあとは画面の下に「元に戻す」が出ます（メメトリップの「元に戻す」を参考にした）。帯が出ている間に続けた操作は、まとめて 1 回で戻せます。
- 旅の当日に開くと、いま居る場所か次の行き先と、あと何分かを一番上に出します（30 秒ごとに進む）。
- 「共有」でプランを文章にして送れます（共有のできない環境ではコピー）。
- 作ったプランと手を入れた分は、このブラウザに取っておきます（再読み込みしても消えない）。最初に開いたときは `server/sample.json`（京都）を見せます。ほかの人が作ったプランは見せません。
- 作成中は「キャンセル」で前のプランに戻れます。初めてのエリアでは、候補が届いている途中はプランを組み替えず、そろったときに 1 回だけ組み直します。
- 地図の右下の現在地のボタンで、現在地を青い点で出します（ブラウザは HTTPS で開いたページにしか位置情報を渡しません）。
- 服装の目安: 予定の時間帯の体感温度（Open-Meteo の apparent_temperature）の平均から 8 段階で出し、傘（降水確率）と寒暖差のひと言を添えます。
- 区間の手段（`lib/geo.ts` の `route`・画面は `components/LegMode.tsx`）: ふだんは「歩いて 20 分以内か、電車・バスの目安の 1.15 倍以内なら徒歩」で自動に選びます。区間を押すと徒歩と電車・バスを選び直せ、選んだ手段は区間ごとに旅に保存します（自動に戻すこともできる）。歩く道の無い 2 点（川や海を挟むなど）には歩く案を出しません。歩くを選んでも、その区間に入れた経路・便は消さずに取っておき、電車・バスや自動に戻すとまた使います。
- ペンギンの一言（`POST /api/penguin`・`server/penguin.py`・`web/src/lib/penguin.ts`）: プランから資料（着く時刻・営業時間・混み方・日の入り・予約・服装など）を組んで送り、Gemini がその日に役立つ注意を 3〜5 行書きます。届いたら服装の目安の札の代わりに出します（閉じると服装の目安に戻る）。資料が落ち着いて 2 秒たってから頼み、同じ資料の答えはサーバーのメモリに 24 時間作り置きして、Gemini を呼ばずに返します。

### 画面（`web/src/`）

- **1 日のプランを「自分だけの路線図」として見せます。** スケジュールは駅ナンバリングのような番号札（01, 02…）と路線の線でつなぎ、公共交通機関は太い実線、徒歩は点線にします。地図の番号札と線も同じ形です（`RouteList.tsx`・`lib/mapLayer.ts`）。
- **混雑する場所での滞在は、このプランとよくある回り方（同じ場所を近い順に回った場合）の 2 本の棒の長さで比べます**（`Compare.tsx`）。混雑をどれだけ減らせたかを、ひと目で見せるためです。
- 色は路線の浅葱 1 色と、混雑の段階（空いている＝淡い灰 → 非常に混雑＝朱）だけ。地図の乗る区間と、区間の行の路線名の印だけは、その路線の色にします。主なボタンは墨。文字は和文が M PLUS 2、時刻と数字が時刻表のような Barlow Semi Condensed。
- 地図は、Google マップのキーがあれば Google マップ（`GoogleMapView.tsx`）、無ければ MapLibre ＋ OpenFreeMap（`MapView.tsx`・鍵なし）。どちらも下地は色を抜いた灰色にし、店や名所の印・地名・道路の名前と番号は出しません（Google マップは `lib/mapStyle.ts`）。地図の上の文字は、プランの番号・名前と出発地だけにします。
- 番号・名前・出発地・所要時間・候補・現在地は、2 つの地図で共通の札の層（`lib/mapLayer.ts`）が描きます。近くの番号は押し離して全部見せ、本当の位置には小さな点を打って細い線で結びます。名前は札の右・左・下・上のうち空いている所に置き、空きが無ければ出しません（拡大すると出ます）。所要時間は、場所を選んだときに前後の区間だけに出します。
- デザインの指針は、Anthropic の frontend-design スキル（題材から見た目を決める・AI が作りがちな見た目を避ける）と、Vercel の Web Interface Guidelines（押せる所・入力・画像・暗い表示などの決まり）を使いました。

## 数字の意味

- **混雑する場所での滞在**: 混雑の推定が「混雑」以上の場所にいる時間の合計です。
- **よくある回り方では**: このプランと同じ場所・同じ滞在を、混む時間を気にせず出発地から近い順に回り、食事はいつもの時間（昼食は 11時30分、夕食は 17時30分を過ぎたら）にとったときの同じ数字です。違いは回る順番と時刻だけなので、混雑を避けて組んだ分の差が出ます（#202）。

## 画面の言葉

Apple と Google のアプリの言い方に合わせます（口語を使いません）。混雑は Google マップの「混雑する時間帯」の言い方
（空いている・あまり混雑していない・やや混雑・混雑・非常に混雑）、天気は Apple の天気の言い方です。

## 言語（日本語・英語）

- 最初の言語はブラウザの言語で決めます（`navigator.languages` の中で先に出る日本語か英語。どちらも無ければ英語）。最初の画面の見出し・入力の画面・調整の画面の「English」「日本語」で切り替えると、このブラウザに残してページを読み直します。URL に `?lang=en` を付けても開けます。
- 言葉は部品ごとに `tr({ ja: {...}, en: {...} })` で持ちます（`web/src/lib/i18n.ts`）。英語の側に抜けや余りがあると `pnpm typecheck` で止まります。英語は Apple のアプリの英語に合わせ、ボタンと見出しは頭を大文字に、文はふつうの書き方にします。
- サーバーへの頼みには言語（`lang`）を付けます。英語のときは Gemini に英語で書かせ（候補の名前・説明・頼みの返事・お題・乗換の読み取り）、候補には日本語の名前（`ja`）も持たせます。地図データ・Places・Wikipedia・Google マップで探すときは日本語の名前を使います。
- 作り置き（候補・希望）と、このブラウザに取っておくプランは言語ごとに分けます。英語に切り替えると、日本語で作ったプランは日本語に戻すまで開きません。
- 時刻表の停留所・系統・行き先は、時刻表（GTFS）の `translations.txt` に英語があれば英語で出します（京都市バスにはある）。無いものは日本語のままです。
- 混雑・役割・タグなどの中で使う印は日本語のままで、画面に出すときだけ言語で引きます。
