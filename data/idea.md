## テーマ「Own the Why」に沿った案（Claude 壁打ち）

- **「理由を書かないと出発できない」旅ガチャ**（観光）
    - Places API で現在地周辺の候補を取得し、Gemini が「近い／遠い」「有名／無名」「屋内／屋外」など対立する3案を、欠点付きで提示する。
    - ユーザーは1案を選んで理由を一言書く。書くと Maps のルートが開く。
    - 帰宅後に「選んだ理由は当たっていたか」を振り返り、理由のログが自分の好みの記録になる。
    - 懸念: 理由を書く手間による離脱（音声入力・選択式で軽くする）、Maps API の料金（無料枠に収まるか要確認）。

- **交差点でミッションが出る散歩**（観光／エンタメ）
    - 交差点でカメラを向けると、Gemini Live API が映像を見て、その場の風景でしか成り立たないミッションを出す（例: 「左の道に赤いものが3つある。数えながら進め」）。
    - どちらに曲がるかは人間が決め、AI はミッション（理由づけ）だけを担当する。帰り道は Maps で案内する。
    - 懸念: 映像のやり取りの遅延、バッテリー消費、歩きスマホの危険。
    - 懸念: 既存アプリ「さんぽ神」と内容が被りそう。差別化が必要。

- **AI が反対側に立つ「推し活の言語化」**（クリエイティブ）
    - 好きな作品の感想を書くと、Gemini は褒めずに「なぜそう感じたのか」を3回掘り下げる（例: 「泣けた」→「どの場面の、何に対して？」）。
    - 最終的に、自分の言葉だけで組み立てた感想文が仕上がる。AI が書き足した文は入れない。
    - 懸念: 質問が的外れだとうっとうしい体験になる。

- **「迷い方」を残す意思決定ログ**（クリエイティブ／教育）
    - 検討した選択肢と捨てた理由を貼り付けると、Gemini が「判断の癖」（いつも安全側を選ぶ、締切を理由に決める等）を抽出し、数か月分を重ねて見せる。
    - ハッカソンの提出項目「AI をなぜ使ったか、何を得たか」の下書きにもなる。
    - 懸念: 記録の習慣が続かない。入力を1タップにするなど軽さが鍵。

- **介護者向けの「今日はやらなくていいこと」リスト**（医療・福祉）
    - 介護者がその日の体力や予定を入力すると、タスクを Gemini が「今日必須／明日でよい／やらなくてよい」に仕分ける。
    - 仕分けの根拠を必ず併記し、最終判断は本人が1タップで入れ替えられる。
    - 懸念: AI 任せに見えるとテーマに反する。根拠表示と入れ替え操作が見せ場。

- **長期休みの「やらないこと」を決める**（エンタメ）【すぐ着手可能】
    - やりたいことを列挙すると、Gemini が所要時間と相性を整理し、「全部は入らない」ことを可視化する。
    - ユーザーは何を諦めるかを選び、その理由を残す。完成した予定は Google カレンダーに書き出す。
    - 最初の一歩: AI Studio にやりたいこと10個を入れて、分類の質を確かめる。
    - 懸念: 普通の予定管理アプリに見えてしまう。「諦める」体験をどう際立たせるか。

- **穴場を引く旅ガチャ**（観光）
    - 現在地周辺の候補のうち、評価が高くて口コミが少ない場所（穴場）だけを対象にランダムで1か所を引く。オーバーツーリズムの分散にもつながる。
    - 混雑状況は API で取得できないため、次の方法で代替する。
        - 人気度: Places API の評価件数（口コミ数）を使う。累積値で「今の混雑」ではないため、同カテゴリ・同エリア内で比較する。
        - 混雑しやすい時間帯: 営業時間・曜日・ジャンルなどの実データを材料に、Gemini が推定する。「推定」と明記し、根拠と確度を添える。
    - 懸念: 口コミが少ないのは「知られていない」「質が低い」場合もある。評価の下限を設ける。
    - 懸念: Gemini の推定は作り話になりうる。実データに寄せ、断定しない。
    - 検証: チームで数か所を実際に訪れ、推定と実感がどれくらい合うかを確かめる。審査での根拠にもなる。
    - 追加要望: オーバーツーリズムを避けつつ、曖昧な要望（「なんかいい感じの所」など）でも、見どころのある観光名所や飲食店を出してくれる。
    - 余裕があれば: 旅行の細かい時間割を組む機能（「メメトリップ」的なもの）。時間と場所を分散させることで、オーバーツーリズムの抑制につなげる。

## 学生チームであることを活かした案（Claude 壁打ち）

- **友達グループの「ズレ」を見せる合意形成アプリ**（エンタメ／教育）
    - 友達グループの各自が別々に「週末にやりたいこと」を入力する。Gemini は多数決を取らず、希望がどこでずれているかを可視化する（例: 「3人は外出派、1人は予算が理由で反対」）。
    - AI は結論を出さず、各自が「なぜそれを選ぶか」を話す順番だけを提案する。
    - 学生は予算・時間・授業の制約が人ごとに違い、ずれが起きやすい。
    - 懸念: 「グループ用の日程調整アプリ」に見える。ずれの可視化の見せ方が勝負。

- **学生の「お金がない」を制約にした旅ガチャ**（観光）
    - 予算（例: 2000円）と時間（例: 半日）を入力すると、範囲に収まる行き先を3つ出す。うち1案はわざと予算を少し超えるようにし、「超えてでも行く理由があるか」を自分で判断させる。
    - 学生は予算が最大の制約で、課題の根拠を実感で語れる。
    - 懸念: 交通費の算出に使う API の料金。

- **サークル・研究室の引き継ぎで「理由」を残す仕組み**（教育）
    - 先輩が書く引き継ぎ資料を Gemini が「なぜそうしているのか」の観点で読み、理由が書かれていない手順を指摘して先輩に質問する。答えた理由は、後輩が読むときに根拠として併記される。
    - GDGoC のような学生団体は毎年代替わりがあり、課題が明確。
    - 懸念: 見栄えが地味。「理由のない手順が見つかる瞬間」をデモの見せ場にする。

## Google の資産を起点にした案（Claude 壁打ち）

- **YouTube の「見たあとに何が残ったか」ログ**（教育）
    - 学習系の動画を見終わった直後に、「この動画で自分の考えが変わった点」を1行書く。Gemini は字幕を読み、書いた内容が動画の内容と食い違っていないかを指摘する。
    - 月末に、見ただけで終わった動画と、考えが変わった動画を並べて見せる。
    - 使う Google 資産: YouTube Data API、Gemini。
    - 懸念: 視聴履歴は API で取りにくく、ユーザーが動画を選ぶ形になる。字幕のない動画は使えない。

- **Google フォトから「あの日の理由」を掘り起こす**（クリエイティブ）
    - 選んだ写真を Gemini が見て、「なぜこの構図で撮ったのか」「何に惹かれたのか」を質問する。AI は講評せず、聞くだけ。
    - 答えを積み重ねると、自分が何に惹かれるかが写真の傾向と一緒にまとまる。
    - 使う Google 資産: Google Photos Picker API、Gemini。
    - 懸念: 取り込みは Picker API の仕様に縛られる。プライバシーの説明が必要。

- **Google ブックスで「反対意見の本」を渡す**（教育）
    - 今の自分の考えを一文で書くと、反対の立場で書かれた本を Google Books から探して紹介する。読むかどうかは自分で決め、読まない場合もその理由を残す。
    - 使う Google 資産: Google Books API、Gemini。
    - 懸念: 本の中身は API で読めず、紹介文や目次の範囲になる。

## 方向性メモ

- 「AI 社会に向けて、自分の好みを明文化して手元に保存する」系が有望。
    - 該当しそうな案: 推し活の言語化、意思決定ログ、Google フォトの「あの日の理由」、「理由を書かないと出発できない」旅ガチャ。

## 方針メモ（チームの話し合い）

- 旅をメインにして、複数のアイデアを1つのプロダクトにまとめる方向。
    - まとめる候補: 理由を書く旅ガチャ、穴場を引く旅ガチャ、曖昧な要望からの提案、旅の時間割、学生の予算制約、友達グループの合意形成、交差点のミッションの散歩。

- **旅行中に1つミッションを出す機能**（観光／エンタメ）
    - 旅の途中でミッションが1つ出る。例: 「地元のスーパーに行く」「食べた料理の写真を送る」。
    - BeReal のように、その場で撮って共有する体験になり、若者に受けそう。
    - 懸念: 「さんぽ神」との重複（交差点のミッションの散歩と同じ）。
    - 懸念: 写真の共有範囲とプライバシー。

- 旅の流れに沿った整理（案）

    | 段階 | 機能 | 元の案 |
    |---|---|---|
    | 出発前 | 予算・時間・友達の希望を入力し、ずれを見える化する | 学生の予算制約、友達グループの合意形成 |
    | 行き先決め | 穴場を3案出し、選んだ理由を書く | 穴場の旅ガチャ、理由を書く旅ガチャ |
    | 旅の最中 | ミッションが1つ出て、写真を撮る | 旅行中のミッション |
    | 旅のあと | 選んだ理由とミッションの写真を振り返り、「自分の好み」として残す | 好みの明文化 |

    - 懸念: 機能が多く、学生4人の期間では全部は作れない。最小構成（行き先決め ＋ ミッション）に絞り、残りは今後の展開として語る。
    - 懸念: ミッションだけでは「さんぽ神」と被る。「穴場を選ぶ理由を書く」「好みの記録」で差別化する。
